# Scopyx 1.1.1

A patch release on the 1.1 surface. The `scopyx` image and its `-chromium` variant, `ghcr.io/taipanbox/scopyx`, are built with Go 1.27.3, which fixes GO-2026-6809 in `crypto/x509`. Version 1.1.0 was built with Go 1.27.2. Nothing is read, emitted, refused or stored differently, and no frozen name in `compat/1.0.json` moved: `scripts/compat-surface.sh` holds that.

## Upgrade

Nothing breaks, and an existing run needs no edit. Pull `ghcr.io/taipanbox/scopyx:v1.1.1` and `ghcr.io/taipanbox/scopyx:v1.1.1-chromium` in place of the 1.1.0 tags. The configuration and the journal are the same. The image sizes in the README are the 1.0.1 measurements and were not re-measured for this release.

## Changed since 1.1.0

- **Go 1.27.3 (#67).** The `go.mod` toolchain, the CI and release `go-version`, and the Dockerfile Go version move from 1.27.2 to 1.27.3, so `govulncheck` is clean again and the published image carries the fixed standard library. No source file of scopyx changes.
- **agent-stack-go v2.0.1 (#66).** A dependency bump that changes `go.mod` and `go.sum` only. The upstream release changes no Go code. Nothing in scopyx's own surface moves with it.

No other commit lies between the 1.1.0 tag and this release.

## Not proven

- Whether GO-2026-6809 was reachable from scopyx's own code under Go 1.27.2 was not measured. The bump removes the question rather than answering it.
- The release and image jobs run only on the tag push.
- The Go version of the shipped binary is read with `go version` from the published image after the tag is pushed.
