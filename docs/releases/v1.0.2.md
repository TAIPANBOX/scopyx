# Scopyx 1.0.2

A patch release on the 1.0 surface. The `scopyx` image, `ghcr.io/taipanbox/scopyx`, is signed in the legacy `.sig` format that the cluster admission controller (policy-controller v0.15.1) reads, so the signature is verifiable there. Its reader takes only that tag, and before this release the image signature was not. cosign stays at v3.1.3, and the release workflow's `sign-blob` steps are unchanged. Nothing frozen in `compat/1.0.json` moves, and no decision changes.

## What changed since 1.0.1

Twenty commits lie between the 1.0.1 tag and this release. The ones that change anything a person sees:

- **Unreadable robots.txt is logged per destination (#60).** Each fetch that proceeds because a robots.txt could not be read now writes one log line: the origin, the mode and the outcome. The path and the query are never logged. The mode and its default are unchanged, so the decision is unchanged.
- **The image is signed in the legacy format (#63).** The image sign steps add `--new-bundle-format=false --use-signing-config=false`, with a comment above each. Remove both flags when policy-controller reads bundles.
- **The agent-stack-go pin moves to the v2 module path, v2.0.0 (#62).** The shared wire-type import moves to `github.com/TAIPANBOX/agent-stack-go/v2`. Nothing an operator sets or sees moves with it.

The rest are dependency bumps, the estate secret-scan workflow (#54), the Go toolchain pin moved to go1.27.2 (#53), the agent-stack-go v1.1.0 to v1.3.0 bumps (#51, #58, #59), the actions bumps (#49, #50, #55), and documentation (#52, #57 and a README correction). The chromium screenshot and `wait_for` implementation (#47) and the agent-stack-go v1.0.1 and v1.0.2 bumps (#46, #48) are in the same range.

## Upgrade

Nothing to change in a deployment. Pull `ghcr.io/taipanbox/scopyx:v1.0.2` and `:v1.0.2-chromium` in place of the 1.0.1 tags. The configuration and the journal are the same. The image sizes in the README are the 1.0.1 measurements and were not re-measured for this release.
